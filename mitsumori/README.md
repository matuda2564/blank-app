# 見積・発注 照合ツール

見積書と発注書(PDF・Excel・画像)を取引先ごとに入れて、型式・品名・数量・単位・単価・金額・納期の違いを探します。

- **社外に書類を出しません**(パソコンの中だけで動きます)。AIには送りません。過去の書類を覚えません。起動時と終了時、リセット時に、作業中の書類を全部消します。
- ✅ 確実に一致 = 文字入りPDF・Excelで全項目が一致 / ☑ 画像で一致 = 2種類の読み取りが一致(**似た文字 0とO・1とI は目で確認**)/ ❌ 違い / ⚠ 要確認。**✅以外は人が見る**。
- 使い方: 社ごとの枠に見積書と発注書を入れる → 「照合する」 → 結果を確認 → 「全部リセット」。

開発: `python mitsumori/server.py 8780` → http://127.0.0.1:8780/  /  試験: `python mitsumori/launcher.py --selftest out.txt`

## 試験(ダミー書類・242組)
`python mitsumori/tests/stress.py <作業フォルダ>` で、わざと間違いを入れた見積・発注書(数量・単価の1桁違い、型式の 0/O・1/I・ハイフン、カタカナ・漢字の違い、行の抜け・増え・重複、合計の誤り など)を作って照合し、**違いがあるのにOKと出した行(見逃し)**を数えます。
最新の結果: 見逃し 0 件 / 文字入りPDF・Excelは誤警報 0 件。画像は安全側に倒れ、読み取りに自信がない行は「要確認」になります。
**似た文字(0とO、1とI)の読み違いは、画像では完全には防げません。** 「☑ 画像で一致」の行は、確認ビューの赤枠で目で確認してください。

## 落ちるときの対策と、ログ(2026-11-26)
- 重い書類で落ちる報告を受け、次を入れた: ①読んだページ画像を圧縮して持つ ②同時に読む数を、パソコンの空きメモリで自動調整 ③メモリが足りないときは、待ってから、読めない旨を表示 ④1書類は先頭40ページまで(超えたら、読んでいないと明示) ⑤大きな写真は縮めて読む(向きも補正) ⑥1ページの失敗で書類全体を捨てない。

## 「1回しか使えない」不具合の修正と、社ごとのリセット(2026-11-26)
- 症状: 1社を照合したあと、B社に書類を入れようとしても反応せず、リセットも押せない。
- 原因: 重い読み取りの最中は、画面が状態を聞いても、返事が数秒遅れる(測定: 最大3.6秒)。照合を始めた直後に出した古い問い合わせの返事(「読み取り中」)が、完了のあとに届き、画面が「読み取り中」のまま固まる。ボタンも枠も無効のまま、二度と更新されなかった。
- 直し: ①古い返事は捨てる(最新の問い合わせの返事だけを使う) ②見張りを、重ならない作りにした ③押した時点の最新の状態で判断する ④4秒ごとに裏の状態と合わせる。

- 試験: `tests/ui_race_test.js`(返事をランダムに0〜4秒遅らせて、照合→社ごとのリセットを3回くり返す)。使い方: アプリのサーバーを起動し、表示されたURLを引数にして `node ui_race_test.js <URL>`(Playwright が必要)。

## 見積 ⇔ 見積(客先に出した見積 と 仕入先の見積)(2026-11-26)

### Windowsの通し試験で見つかった不具合(2026-11-26)
- 症状: アプリを、日本語の名前のフォルダに置くと、2つ目の読み取り(Tesseract)が動かず、画像の書類が、ほぼ全部「要確認」になる(落ちはしない)。
- 発見: ビルドの通し試験(日本語の名前の場所・日本語のTEMP)。ソースのままは合格・exeは不合格。
- 直し: 同梱のTesseractが、日本語の名前の場所にあるときは、英数字だけの場所(`C:\Users\Public\mitsumori_check_tess` など)に、初回だけコピーして使う。Tesseractが失敗したときは、終了コードと理由を、ログに残す。

## 「アプリなのに、ブラウザで開く」への対応(2026-11-26)
- 症状: アプリ(exe)を起動すると、専用の窓ではなく、ブラウザ(Edge)で画面が開く。
- 原因: ①専用の窓を開けなかったとき、エラーを握りつぶして、黙ってブラウザを開く作りだった(理由が、画面にもログにも、残らなかった) ②窓を開く試験を、Windowsで、1度もしていなかった ③窓を動かす部品(pythonnet / clr_loader)が、同梱されていない可能性。
- 対応: ①窓を開けなかった理由を、ログと、小さい窓に出す ②ビルドで、窓が開くかを試す(`--windowcheck`・参考扱い) ③pythonnet / clr_loader を、同梱するようにした。
- 窓が使えないパソコンでは、ブラウザで開く(使い方は、同じ)。Windows10などで、Edge WebView2 が無いことが、原因のこともある。

## 「127.0.0.1 接続が拒否されました」(ERR_CONNECTION_REFUSED)への対応(2026-11-26)
- 症状: ブラウザに、「このページに到達できません / 127.0.0.1 接続が拒否されました」。
- 意味: 画面の裏の、小さなサーバー(アプリの中)が、動いていない。アプリが終了したか、止まったか、古い画面(履歴・ブックマーク)を開いた(つなぎ先の番号は、起動のたびに変わる)。
- 落とし穴だった点: 専用の窓が開かず、ブラウザで開いた場合、出てくる小さい窓を閉じると、アプリ全体が終了し、ブラウザの画面だけが残った。
- 対応: ①小さい窓を閉じても(×を押しても)終了しない(最小化するだけ) ②ブラウザの画面が開かれている間は、動き続ける。画面を全部閉じて3分たつと、自動で終了(書類も消える) ③小さい窓に「画面を開き直す」「終了する」ボタン ④画面が切れたとき、「アプリを開き直して、新しく出る画面を使う」と案内。
- 落ちた場合の原因調査は、`%LOCALAPPDATA%\mitsumori_check_log.txt`(強制終了の場所も、ここに残る)。
- 試験: `--smoke`(画面の問い合わせで時刻が更新される)/ `tests/idle_exit_test.py`(画面が開いている間は動き、閉じて、期限後に自動で終了する)

## 見積⇔見積: 型番だけを拾う方式と、向きの自動補正(build 13)

## 見積⇔見積: 読む列を決める(build 14)
- 見積書と発注書(見積同士)は、宛先・日付・備考・納期・住所・金額などが違って当たり前なので、そこから拾った文字を「違い」にしない。
- ページごとに表の見出し(数量+品名/型式など)を探し、**「数量・単価・金額」の列より左(型式・品名の列)だけ**を読む。見出しの下から、合計・備考・以下余白の手前までが明細。
- 見出しが見つからないページは、そのページ全体から拾い、画面の「読んだ範囲」に、その旨を出す(精度が下がる)。
- 型番にしない: 電話・インボイス番号・郵便番号・単位つきの数字・3/8 のようなインチ寸法。
- 試験: tests/qq_region_test.py(右の備考・宛先・末尾の注記の型番らしい文字を拾わない)。実物4枚で確認(型番 B9565AW-T / AE20-133 のみ)。
- 未対応: 画面で列を直すプルダウン。見出しが読めない書類は、まだ「全体から拾う」になる。

## 見積⇔発注: 型式の列が無い書類にも対応(build 15)
- 実物(国際チャートの見積・FAX注文書・宇野の発注書)で、「相手が決まらない」「型式が読めない」となった原因: 表に型式の列が無く、品名の欄の2行目に型番が書いてあった。
- 型式は、型式・品名の列(数量より左)から型番らしい文字列を拾い、数量・単価・金額は、見出しの列の位置に合う数字を読む。型番は、いちばん近い数字の行に付ける。
- 「単 価」が1字ずつ分かれた見出しや、画像で「|単位|単価」とくっついた見出しも扱う。
- 組にするとき、型式の重なりが同点なら、発注書のどこかに見積番号が書いてあることを決め手にする。
- 画像は、型式が2種類の読み取りで一致し、数量・単価・金額も確かめられたものだけを「確実」にする(確かめられなければ要確認)。
- 試験: tests/qo_rows_test.py。実物4枚で、見積(316386-1)⇔FAX注文書が組になり、宇野の発注書(圧力計)は、対応する見積がないので組にならない。

## 見積⇔発注: 照合エンジンを作り直した(build 21・qo_engine.py)
**きっかけ**: 実務では、①見積どおりに発注が来ない(品目が減る・増える・数量が変わる) ②お客様が見積番号を書いてくれないことがある ③見積2枚が発注書1枚に収まる/見積1枚が発注書2枚に分かれる、がある。従来は「見積1枚⇔発注書1枚」「見積番号か型式の重なりだけ」で、まとめ入れ(5社・15枚ずつ)では、半分近くの行が判定されなかった(下の採点)。
**判断の順番**(上で決まらないときだけ下): ①会社名 → ②見積番号 → ③型番(書き方の違いは同じ・1〜2文字違いは人に確認) → ④品名(型番の無い行・単価か金額が合うときだけ) → ⑤数量・単価・金額。**書類ごとではなく、行ごと**にひもづける。
- 発注書にあって見積に無い品目 = ❌「見積に無い品目」。見積にあって発注書に無い品目 = 📋「発注されなかった品目」(エラーではないが必ず知らせる)。

## 単価・金額は比べない(build 27・松田さんの指示)
- 見積と発注書で、**単価・金額は違って当たり前**なので、比べない。判断するのは **型式・型番・品名(と、数量の違い)**。
- 型番が同じでも、**品名がまるで違えば「要確認」**(別の品目の可能性)。品名は、短いほうが長いほうに含まれていれば「近い」とみなす(納期・金額などの文字は、品名から除く)。**画像(FAX)の日本語は読み間違いが多いので、画像の書類では品名で判定せず、「画像のため、目で確認」と出す**。
- 単価・金額は、「同じ型番が複数の見積にあるとき、どれにひもづけるか」の手がかりにだけ使う(違っても、違いとして出さない)。画像の読み取りで、単価・金額の列が読めなくても、問題にしない。

## 範囲コピーのオン/オフ + 文字にカーソルを合わせて押すとコピー(build 32・めぐみさんの要望)
- 拡大画面の「📋 範囲コピー」を**スイッチ**にした。
  - **オン**: 画像は**動かない**。左クリックでなぞった四角の中の文字を、まとめてコピー。
  - **オフ**(初期): 画像は、引っぱって**動かせる**。さらに、**文字にカーソルを合わせると**、その場所に「📋 押すと、**型式**をコピー: ○○」「**品名**をコピー」「**個数**をコピー」などと案内が出て(文字には緑の色がつく)、**動かさずに押すと、その文字だけコピー**される。引っぱると、コピーせずに、画像が動く。ダブルクリックは、元の位置に戻す(コピーしない)。
  - 型式・品名・個数は、その行の中身(行全体の型式・品名)をコピーする。行に結びつかない文字は、「この文字」として、その文字だけコピー。
- Shiftを押しながらなぞると、スイッチに関係なく範囲コピー。
